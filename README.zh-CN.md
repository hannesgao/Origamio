# Origamio

[English](README.md) · 中文

又一个折纸模拟器：在浏览器里沿任意直线折一张方形的纸，看着层一层层叠起来，随时展开检查折痕图并数出得到的面数。

**试一试：** <https://origamio.hannesgao.workers.dev/>

Origamio 是一个纯前端应用（Vite + TypeScript，不用框架；唯一的运行时依赖是 three.js，只用于 3D 卡片）。平面视图由一个小巧、不可变的几何模型渲染成 SVG，所以每一次折叠都是精确的：反射加凸多边形裁剪。3D 卡片把这个模型当作一张纸来求解（在 Web Worker 里，界面从不等它），再用 WebGL 画出来；没有 WebGL 时 3D 卡片显示一条说明，其他视图照常工作。

## 功能

- **沿任意直线折，或点对点折。** 用 _画线_ 工具在折叠后的纸上拖出一条折线，再单击要翻过去的一侧。用 _对点_ 工具把一个角（或任意一点）拖到它应落到的点上：纸沿两点之间的中垂线折叠，正如折纸图解的写法。端点会吸附到折叠后纸张的角、边的交点、边的中点和边上，所以"角对角"或"角对中心"是精确的；按住 Alt 可自由画线。
- **折全部层或只折最上面的 _k_ 层。** 单击之前先选择是折整叠纸还是只折最上面几层。
- **实时展开图。** 展开视图显示重新摊平的纸，每条折痕用红色画出，并附正面、背面和折痕颜色的图例。
- **按层数着色。** 面是半透明的，所以一个区域每叠上一层就更深一点。背面朝上的面用更深的底色。
- **翻折动画。** 移动的纸片绕折线旋转约 0.8 秒，经过垂直位置时切换成背面的颜色。
- **统计。** 折叠次数、任意一点的最大层数、展开图的面数，以及指针下的层数。
- **预设。** 对折三次；或者对折两次，再折三种角之一：四个纸角叠在一起的松角、两条折边相交的角，以及只有一条折边的角。
- **任意纸形和颜色。** 纸张面板提供正方形、A 系列、4:3、3:2 和 16:9 的纸、自定义宽高、一个旋转按钮、六组正反面配色和两个取色器。更改尺寸会回到平展的纸并保留时间轴上的每一步；更改颜色立即生效。尺寸和颜色是每个导出文件的一部分，导入时恢复。
- **跳蛙。** _跳蛙_ 预设用 1:2 的纸：上面的正方形收成水雷基本形，两侧的半边塞进两个面之间，前面的角向上向外折成腿，两侧内折，底部折成弹跳的褶。每一步都是真纸能做到的平折，并且每一步都有测试检查这一点。
- **纸鹤。** _纸鹤_ 预设用 12 步播放经典的折法，其中好几步同时折出不止一条折痕：预折对角线、收成方形基本形（两条中线，再把四个翼压开成并排的壁板）、把正面和背面的页花瓣折成鸟基本形、收窄两个尖角、沿中线合拢模型、内翻折脖子、尾巴和头，最后展开翅膀：最后一步把每只翅膀向上翻到身体的各自一侧，折痕保持 100° 的开角，纸鹤因此在 3D 视图里站得起来。每一步都让纸处在真纸能达到的状态：测试检查相邻的面从不被扯开。
- **带真实折痕的 3D 视图。** 第三张卡片把纸显示为在折痕处相连的刚性面板，并按纸的物理来求解：每条折痕被拉向它的角度（平折的折痕打开几度，_开角_ 芯片提供 0°、6°、15° 和 30°，旁边的输入框接受最高 90° 的任意值，层叠得多的地方开得少；折到指定角度的折痕保持该角度），同时每块面板保持尺寸，在折痕处相连的面板保持相连。当角度互相矛盾时，比如纸鹤的翅膀和身体，纸会像真纸那样让步并取一个折中：面板可以沿对角线微微弯曲，然后折痕才让步，所以纸鹤能翅膀展开、身体合拢地站着。平面模型中互相叠压的层保持原来的顺序：任何一层都不穿过另一层是硬规则，每一层比下面一层高出一个纸厚只是偏好，因为在折痕或尖端处焊在一起的层不可能相隔一个纸厚。它用 WebGL（three.js）绘制：纸有厚度（_纸厚_ 芯片对 15 cm 的纸提供 0、0.07 和 0.2 mm，或者输入任意值）、柔和的主光、模型下方的地面阴影（俯视图中隐藏）、只在纸弯折或结束处画折痕线，另一层贴近覆盖的地方纸会变暗，于是身体内部的缝隙读起来像口袋，展开的翅膀依然明亮（这是从求解后的纸面算出来的，因为屏幕空间遮蔽看不进纸那么薄的缝）。_透视_ 在透视画面和正投影画面之间切换，后者让固定视图成为没有近大远小的真正图纸。拖动可以任意转动，滚轮缩放，_正视_、_侧视_、_俯视_ 和 _等轴_ 分别是模型的正、侧、顶和等轴固定视图（序列可以说明它的模型怎么站立；纸鹤说明了，没有说明的模型按它的形状取景，长轴前后向）；_复位_ 回到默认角度。步骤播放时，它的折痕在三维里从平展摆到折叠，摆向活动纸落地的一侧；活动的纸被挡在它靠近的纸之外，挡在完成步骤的层序所规定的一侧，所以纸片会把层推开而不是穿过去。折到内部、夹在层间的纸两侧都通过折痕连着静止的纸，往哪边都无法刚性摆动：它按多数折痕的方向走，不一致的折痕在本步松开，所以内翻折能干净地摆过去。被固定的面在纸沉降之后再放回刚体行走给它的位置，而不是沉降时钉住，因此位于层堆中间的锚点不会卡住两侧的层。保存时带有小于 180° 的 `angle` 的步骤会保持该开角。在任一视图里指向一个面，其他视图会勾勒出同一个面；指向折叠后的纸会勾勒出指针下的每一个面。
- **浅色和深色主题。** 界面跟随操作系统的配色方案。
- **四种语言。** 英语、中文、日语和德语，在标题栏的菜单里选择，记在浏览器里，首次按浏览器语言；地址里加 `?lang=ja` 可以给链接指定语言。内置序列的名称和步骤名也会翻译；你自己输入的名称原样保留，文件里始终存英文名。
- **可编辑的时间轴。** 每个片段都可以重命名（双击或 F2）、拖到别的位置、复制、删除（Delete）或连同之后的全部截掉，都在右键菜单里。手动折的一步插在播放头处，后面的步骤保留。编辑用 Ctrl+Z 和 Ctrl+Shift+Z 撤销和重做，与播放头无关。因为每一步的折线写在那一刻纸的坐标里，编辑后不再移动任何东西的步骤会用红色斜线标出，方便修正。
- **步骤检查器。** 侧栏的步骤面板编辑选中的步骤：名称、移动的层（全部、上 _n_ 层、下 _n_ 层）、移动的纸落在哪里（上方、下方、内部）、哪一侧移动、折线的两个点，以及预设步骤带有的区域或窗口限制。_重画折线_ 回退到该步之前，把你接下来在折叠后的纸上画的线作为它的新折线。
- **时间轴、回放、导入和导出。** 每一次折叠，无论手动还是来自预设，都落在视图下方的剪辑式时间轴上：一把标尺、每步一个片段，以及可拖动的播放头。前后单步（也可用方向键）、在任意一步播放和暂停、选择播放速度、单击片段或拖动跳转。预设只加载步骤；是逐步看还是播放由你决定。播放头之后的步骤保留在时间轴上；手动折的一步插在它们前面。整条时间轴可以保存为 JSON 文件并在以后再加载；预设以同一格式提供。
- **三种布局。** 标题栏在 _大折叠图_（默认：折叠视图占据工作区的大部分，旁边第二张卡片用头部的标签页显示折痕图或 3D 视图）、_并排_（三个视图排成一行）和 _专注_（一次一个视图，用工作区上方的标签页选择）之间切换。折叠画布尽卡片所能放大，无论窗口比例；_并排_ 和 _专注_ 下其他画布保持正方形，_大折叠图_ 下第二张卡片填满它那一列。所有这些选择都记在浏览器里。
- **为宽屏设计。** 标题栏、侧栏和状态栏固定，视图按剩余空间定尺寸，所以在 16:9 的显示器上什么都不用滚动。窄于 1340 px 的窗口一次显示一个视图，用折叠 / 展开 / 3D 标签页切换；900 px 以下面板浮在工作区上方，手机上（700 px 以下）播放控制固定在底边。

## 使用模拟器

页面是一个填满窗口、整体从不滚动的工作台：固定的标题栏里有序列名称（就地编辑）和布局切换，左侧的图标栏打开预设库（分组的预设）、纸张（尺寸和颜色）、步骤（选中步骤的参数）、文件（名称、导入、导出、新建）和快捷键面板，工作区里是三张视图卡片和下方的时间轴卡片，底部的状态栏显示带两种颜色的纸、时间轴上的位置和最新的消息（加载了什么、某次折叠做了什么、文件为何被拒绝），右侧是署名、版本和构建时间（德国时间，精确到分钟，用来区分不同的部署）。每张视图卡片结构相同：头部有标题和卡片的统计数字靠右（折叠视图是折数、层数、面数和指针下的层数；折痕图是折痕数），一行工具，每个是图标加关键词（窄卡片上关键词让位），画布，以及下方一行参数和提示（折叠视图是状态行和缩放；折痕图是图例；3D 视图是 _开角_ 和 _纸厚_ 芯片），所以三张卡片逐行对齐，画布高度一致。视图按剩余空间定尺寸。所有操作都在折叠卡片里：拖动工具、层选择、缩放和状态行。

1. **画折线。** 用 _画线_ 工具在折叠后的纸上按下、拖动、松开。蓝色虚线显示折线的位置；短于纸张 2% 的拖动会被忽略。画线时，折叠后纸的角、边的交点和边的中点显示为圆点，端点在几个像素内吸附到最近的一个（或吸附到边上）；一个圆环标出吸附点，状态行说出它是什么。_吸附_ 按钮关闭吸附，Alt 让单次拖动跳过它。折叠落到时间轴的播放头处。手动的折叠会把连在活动层上的纸一起带走，真纸必然如此；折叠后的消息会说明连带了多少个面。
2. **选择一侧。** 把指针移到折线的任一侧；将要翻转的一侧有阴影。单击即翻过去。按 Esc 则放弃这条线。
   **或者点对点折。** 用 _对点_ 工具按住一个角（或任意一点），把它拖到应落到的点上。折线是两点的中垂线，含第一个点的一侧移动，所以松开的瞬间就完成折叠；拖动时虚线和阴影预览结果。大多数折纸图解就是这样写的（"把角折到中心"），加上吸附，结果是精确的。
3. **选择移动几层。** 折叠工具栏里的 _全部 / 上 n_ 控件作用于下一次折叠：_全部_ 折整叠纸，_上 n_ 只折上方少于 _n_ 个不同层的面。
4. **看结果。** 折叠后的纸下方的状态行告诉你当前在哪一步，卡片头部的统计（折数、最大层数、面数、指针下的层数）每折一次就更新。
5. **选择纸张。** 纸张面板（侧栏第二个按钮）显示当前的纸，并让你选一种形状或输入宽和高；惯例上长边为 1。每个预设都带着它所用的纸（正方形，或跳蛙的 1:2 纸），所以加载预设会设置那张纸，尺寸变化时状态行会说明。
6. **试试预设。** 预设库面板（侧栏第一个按钮）列出预设；单击一个就把它的步骤从平展的纸加载到时间轴上，然后逐步看或播放。Esc 或 × 关闭面板。
7. **回放和分享。** 视图下方的时间轴卡片有走带按钮（开头、后退一步、播放或暂停、前进一步、结尾）和速度菜单（四分之一倍速到四倍速）；位置和最新消息在窗口底部的状态栏里。主体部分把步骤显示为编号轨道上的片段：实心片段已应用，虚线片段还未应用，红色播放头停在最后一个已应用步骤之后（步骤动画时它会滑动），红色斜线标出在当前位置不再移动任何东西的步骤。按暂停、P 或 Esc 时播放在当前步骤结束后停止。单击片段选中它并跳到该步结束处；在标尺上拖动逐步拖放；拖动片段移动它；双击重命名；右键菜单可重命名、复制、移动和删除。_轨道_ 按钮隐藏轨道；该选择和速度都会被记住。侧栏的文件面板给序列命名、把时间轴导出为 JSON、把这样的文件导入到新纸上，以及用 _新纸张_ 清空步骤（纸的尺寸和颜色保留）。
8. **在空间里看。** 3D 卡片按 _开角_ 设置把每条折痕打开后显示折叠后的纸（0° 显示平展状态，即模型真实的样子；选一个芯片或输入一个值）：拖动旋转，滚轮缩放。四个固定视图跟随加载序列的 `view` 取景框（纸鹤的脸朝对角线上方，背朝另一条对角线）；没有取景框的序列按折叠后纸的形状取景，长轴前后向。把指针移到展开图或 3D 视图里的一个面上，可以看到它在折叠后的纸里的位置；移到折叠后的纸上，可以看到指针下叠着的所有面。
9. **看得更近。** 折叠后的纸很快就变小了，所以折叠卡片有自己的导航：_适合_ 把折叠后的纸框进视图，_全图_ 再次显示整张纸，滚轮以指针为中心缩放，_移动_ 工具（或按住空格，或鼠标中键）可以拖动视图。触摸屏上双指捏合缩放、双指平移。缩放和位置在折叠和撤销之间保留；_全图_（或 0）回到整张纸，加载序列会重置视图。

键盘快捷键：

| 按键                     | 动作                           |
| ------------------------ | ------------------------------ |
| Ctrl+Z（macOS 上 Cmd+Z） | 撤销时间轴的上一次编辑         |
| Ctrl+Shift+Z / Ctrl+Y    | 重做一次编辑                   |
| Delete / Backspace       | 删除选中的步骤                 |
| F2                       | 重命名选中的步骤               |
| Esc                      | 取消折线、关闭面板或菜单、暂停 |
| F                        | 让折叠后的纸充满视图           |
| 0                        | 显示整张纸                     |
| 空格（按住）             | 拖动平移而不是画折线           |
| → / ←                    | 在时间轴上前进或后退一步       |
| P                        | 播放或暂停剩余步骤             |
| Home / End               | 跳到平展的纸或最后一步         |

## 开始使用

需要 Node.js 24（见 `.nvmrc`）。

```sh
npm ci
npm run dev        # 启动开发服务器
npm run build      # 静态站点输出到 dist/
npm run preview    # 在本地预览生产构建
```

构建使用相对资源路径（`vite.config.ts` 中 `base: './'`），所以 `dist/` 的内容可以放在任何静态主机或子目录下，无需配置。

### 质量检查

```sh
npm run lint          # ESLint（typescript-eslint strict + stylistic）
npm run format:check  # Prettier
npm run typecheck     # 带严格选项的 tsc --noEmit
npm test              # tests/ 下的 Vitest 测试
npm run build
```

`npm run format` 就地重写文件。`ci` 工作流在每个拉取请求和每次推送到 `main` 时运行的正是这些命令。

### 部署

站点以静态资源的形式从 Cloudflare Workers 提供；`wrangler.jsonc` 指定 Worker 的名字（`origamio`）并指向 `dist/`；站点上线于 <https://origamio.hannesgao.workers.dev/>。`deploy` 工作流通过 Wrangler CLI 构建并部署每一次推送到 `main` 的提交，使用两个仓库密钥：`CLOUDFLARE_API_TOKEN`（用 _Edit Cloudflare Workers_ 模板创建的 API 令牌）和 `CLOUDFLARE_ACCOUNT_ID`。要从本机部署：

```sh
npx wrangler login   # 一次性；会打开浏览器
npm run deploy       # 构建，然后把 dist/ 上传为 Worker 的资源
```

`npx wrangler deploy --dry-run` 只检查配置，不上传。

### 截图

拉取请求和视觉检查所需的浏览器截图都通过同一个辅助脚本完成，它用 Playwright 驱动无头浏览器：

```sh
npm run dev                                   # 在一个终端里
npm run shot -- --out shots                    # 页面的一张截图
npm run shot -- --out shots --scenario scripts/scenarios/preset.mjs
```

场景是一个 ES 模块，默认导出接收 Playwright 的 page 和一个 `shot(name)` 助手；`scripts/scenarios/preset.mjs` 加载一个预设（由 `SHOT_PRESET` 指定，默认纸鹤）并截取页面和折叠后的纸。辅助脚本还接受 `--width` 和 `--height` 指定窗口、`--dark` 使用深色主题、`--full-page`、`--name` 指定图片文件名，以及 `--browser auto|wsl|linux|windows` 选择浏览器（CI 用的是 `linux`，带软件 WebGL）。它优先使用 Playwright 自带的 Chromium（`npx playwright-core install chromium`，Linux 或 WSL 上再一次性执行 `sudo npx playwright-core install-deps chromium`），从 WSL 运行时回退到 Windows 上安装的 Chrome，每次运行使用全新的临时配置目录，结束后关闭并删除。它从不按名字结束浏览器进程。`shots/` 被 git 忽略。

`ci` 工作流的 `shots` 任务守护图片本身：它提供构建产物，在 Playwright 的 Chromium 里用软件 WebGL 运行 `scripts/scenarios/baseline.mjs`（`npm run shot:ci`），把纸鹤的四个固定 3D 视图、折叠视图和折痕图与 `tests/shots/` 里的基线比较（`npm run shot:compare`，最多允许 0.3% 的像素不同）。有意改变图片的改动要附上新基线：下载该任务的 `shots` 产物，或在 Linux 上运行这两条命令，然后 `npm run shot:compare -- --update` 并提交 `tests/shots/`。

## 数据模型

纸是**展开**纸张坐标系中的一个矩形（默认为单位正方形）。它表示为一组 _面_（`src/paper.ts`）：

| 字段        | 含义                                                                     |
| ----------- | ------------------------------------------------------------------------ |
| `poly`      | 展开纸坐标系中的凸多边形。面在这个空间里从不重叠；它们合起来铺满整张纸。 |
| `transform` | 二维仿射变换（若干反射的乘积），把展开坐标映射到当前折叠后的位置。       |
| `z`         | 层索引。值越大越靠近观察者。                                             |

一次折叠 `fold(state, line, side, options)` 的过程如下：

1. `line` 在**折叠**坐标系中给出，`side` 说明哪个半平面翻过去，`layers` 是 `all`、"上 _k_ 层"或"下 _k_ 层"。一个面属于上 _k_ 层，当它当前位置上方少于 _k_ 个不同的层。选择还可以进一步限制在展开纸的凸 `region` 内或折叠纸的凸 `window` 内；脚本化的序列用它来折纸的某个具名部分。
2. 每个选中的面被这条线切开。线通过逆变换拉回到面自己的坐标系，多边形被裁成留下的部分和移动的部分。
3. 移动的部分把沿折线的反射复合到它的 `transform` 上（`reflection ∘ transform`）。留下的部分保持原变换。两者都保留展开坐标中的多边形。
4. 移动的面按 `placement` 放置：放在层堆的 `top`（顶部），层序反转，正如真实的纸片落下那样；放在 `bottom`（底部），即前者的镜像，用于在模型背面做的折叠；或放在 `inside`（内部），即它们被切出来的那些层之间，这正是内翻折对一个尖角做的事。
5. 每个真正被切开的面记录一条折痕：折线在该面内的弦，以展开坐标存储。

因为每个面都保留展开多边形，展开图就是所有 `poly` 加上所有折痕线段。面数就是面的个数，最大层数是所有面的边构成的排列中最深单元的深度，通过在每个排列顶点内侧稍作探测得到。

面的变换是反射的复合，所以当面当前显示背面时行列式为 −1；渲染器据此选择面的颜色。

应用把每一步保存在一条 `Timeline` 上（`src/timeline.ts`）：状态从平展的纸重放并缓存，每次编辑都拍一个快照，所以 Ctrl+Z 和 Ctrl+Shift+Z 撤销和重做编辑与播放头无关（保留最近 100 次），手动折叠若不移动任何东西会在插入前被拒绝。状态从不被修改。`src/paper.ts` 里的 `FoldHistory` 是测试用来折叠的普通状态栈。

### 语言

界面显示的每一个词都在 `src/i18n/en.ts` 里，按出现位置分组；带值的消息是函数，所以每种语言按自己的语序造句。`src/i18n/index.ts` 从英文表推导出 `Messages` 类型，其他语言（`zh.ts`、`ja.ts`、`de.ts`）按它定型，翻译里漏掉一个词就编译不过。当前语言的词通过 `t` 读取；切换语言会就地替换它们，并以同一序列、同一步骤重建页面。内置序列的名称和步骤名通过同一张表里的 `presets` 和 `stepLabels` 翻译，键分别是预设 id 和文件里存储的英文步骤名；`tests/i18n.test.ts` 检查每个内置名称在每种语言里都有条目。要添加一种语言：复制 `en.ts` 并翻译，把它加到 `index.ts` 的 `LANGUAGES` 和 `loaders` 以及 `ui.ts` 的语言名里，如果它的文字需要，再在 `style.css` 里给它一组字体。

### 序列文件

预设放在 `presets/*.json` 里，你折的任何东西都可以导出为同一格式：一个保存纸张和每一步的项目文件。文件是一个对象，含 `format` `"origamio-sequence"`、`version` `1`、一个 `name`、可选的 `description`、可选的 `paper` 和一个 `steps` 列表。`paper` 保存以纸单位计的 `width` 和 `height`（边长在 0 到 10 之间）以及十六进制的正反面颜色 `front` 和 `back`；没有 `paper` 表示默认橙棕配色的单位正方形，缺少的颜色也同样取默认值。每一步是对那一刻的纸调用一次 `fold`：

```json
{
  "line": [
    [0.5, 0.207107],
    [0.207107, 0.5]
  ],
  "side": 1,
  "layers": { "top": 1 },
  "region": [
    [0, 0.5],
    [0.5, 0.5],
    [0.5, 1],
    [0, 1]
  ],
  "placement": "inside",
  "label": "Petal fold"
}
```

| 字段        | 含义                                                                                                               |
| ----------- | ------------------------------------------------------------------------------------------------------------------ |
| `line`      | 折线上的两个点，用该步的**折叠**坐标（单位纸，原点在左下）。                                                       |
| `side`      | `1` 或 `-1`：有向直线左侧或右侧的半平面翻过去。                                                                    |
| `layers`    | `"all"`（默认）、`{ "top": k }` 或 `{ "bottom": k }`。                                                             |
| `region`    | 可选，**展开**坐标中的凸多边形；只有其中的面参与。                                                                 |
| `window`    | 可选，**折叠**坐标中的凸多边形；只有其中的面参与。                                                                 |
| `placement` | `"top"`（默认）、`"bottom"` 或 `"inside"`，见上文。                                                                |
| `angle`     | 可选的折叠角度（度），范围 `(0, 180]`；小于 180 时 3D 视图让折痕保持该开角。`also` 里的折叠也可以带它。            |
| `attached`  | 可选的 `true`：与选中的面通过折线以外的任一边相连的面一起带走，纸因此从不撕裂。                                    |
| `also`      | 可选，同一步里接着做的更多折叠（`line`、`side`、`layers`、`region`、`window`、`placement`、`angle`、`attached`）。 |
| `label`     | 可选，时间轴上显示的名称。                                                                                         |

序列还可以带 `"view": { "front": [x, y], "top": [x, y] }`：终态折叠坐标中的两个方向，`front` 指向模型的脸外，`top` 沿它的背向上，它们定义 3D 卡片的固定视图（正、侧、顶和等轴）。没有它时，视图按折叠后纸的形状取景：长轴前后向，没有长轴时用纸自己的坐标轴。

`src/sequence.ts` 解析和校验文件（错误会指出出问题的字段），并把点保持在一行上序列化。预设文件由 `src/presets.ts` 里的几何生成：`npm run presets:write` 重写它们，过期时 `npm test` 会失败。

## 参与贡献

`main` 受 `protect-main` 规则集保护：改动只能通过拉取请求合入，且 `ci` 和 `pr-hygiene` 检查必须在与 `main` 保持同步的分支上通过，以 squash 方式合并，历史保持线性（不能强制推送，不能删除分支）。

检查所强制的约定：

- **分支与合并。** 在功能分支上工作，向 `main` 发起拉取请求，squash 合并。squash 提交采用拉取请求的标题和描述，合并后分支自动删除。
- **Conventional Commits。** 提交信息和拉取请求标题形如 `type(scope): summary`（`feat`、`fix`、`docs`、`refactor`、`test`、`ci`、`chore` 等），用祈使语气，最多 72 个字符。
- **拉取请求模板。** `.github/pull_request_template.md` 要求说明做了什么、为什么、如何测试、界面改动的截图和一份清单。
- **卫生检查。** `pr-hygiene` 工作流拒绝标题、描述、提交信息或文件列表中含有仓库变量 `FORBIDDEN_PATTERNS` 里任一模式的拉取请求，例如工具署名的页脚和尾注。仓库也不包含编辑器助手或 AI 工具的配置文件。

### 发布

每次合并到 `main` 都会部署；发布是给值得命名的版本做个标记。`release` 工作流只强制一条真正重要的规则（标签必须等于 `v` + `package.json` 里的版本），并把构建好的站点作为 `origamio-<version>.zip` 附到发布上，供想自行托管的人使用。

1. 发起一个把 `package.json` 里的 `version` 升高的拉取请求（状态栏显示它）并合并。
2. 在 GitHub 上起草新发布：在 `main` 上创建标签 `v<version>`，写说明（改了什么、已知限制、与序列文件格式有关的事项）并发布。
3. 发布会触发 `release` 工作流，它从标签构建并上传 zip。也可以在 Actions 页面对已有标签手动运行。

序列文件的版本与应用分开：格式版本 1 是稳定的，以后的任何版本都能读取它。
